# منصة مؤسسة سنكري التعليمية

منصة بثلاث تبويبات: ميثاق المؤسسة، والإدارة التنفيذية، واللجان المستقلة.

## محتويات الحزمة

| الملف | وظيفته |
|---|---|
| `index.html` | المنصة كاملة (التصميم والشعار والبرمجة). تعمل وحدها أيضاً إذا فُتحت مباشرة على الجهاز. |
| `content.json` | كل نصوص المنصة. هذا الملف الوحيد الذي يتغيّر عند التعديل. |
| `.github/workflows/pages.yml` | ينشر المنصة تلقائياً على GitHub Pages بعد كل تعديل. |
| `.nojekyll` | يمنع GitHub من معالجة الملفات بطريقة تغيّرها. |

---

## 1. الرفع على GitHub (مرة واحدة)

1. أنشئ مستودعاً جديداً على GitHub، مثلاً باسم `sankari-platform`.
   - إذا كان المستودع **خاصاً (Private)** فالنشر على GitHub Pages يحتاج حساباً مدفوعاً. المستودع **العام (Public)** يعمل مجاناً.
2. ارفع كل محتويات هذا المجلد إلى المستودع، بما فيها المجلد `.github` والملف `.nojekyll`.
   - إذا رفعت من موقع GitHub بالسحب والإفلات، فبعض أنظمة التشغيل تخفي الملفات التي تبدأ بنقطة. تأكد أنها ظهرت في المستودع بعد الرفع.
3. افتح **Settings ← Pages**، وتحت **Build and deployment** اختر **Source: GitHub Actions**.
4. افتح تبويب **Actions** وانتظر انتهاء «نشر المنصة على GitHub Pages» (علامة خضراء).
5. رابط المنصة يكون بالشكل:
   `https://اسم-الحساب.github.io/sankari-platform/`

---

## 2. تجهيز مفتاح الحفظ (مرة واحدة)

المفتاح هو ما يسمح للمنصة بحفظ تعديلاتك في المستودع. بدونه لا يستطيع أحد الحفظ، حتى لو دخل وضع التحرير.

1. من GitHub: **Settings (إعدادات حسابك) ← Developer settings ← Personal access tokens ← Fine-grained tokens ← Generate new token**.
2. **Token name**: مثلاً `sankari-platform-editor`.
3. **Expiration**: اختر المدة التي تناسبك (مثلاً سنة).
4. **Repository access**: اختر **Only select repositories** ثم مستودع المنصة فقط.
5. **Permissions ← Repository permissions ← Contents**: اختر **Read and write**.
6. اضغط **Generate token** وانسخ المفتاح (يبدأ بـ `github_pat_`). لن يظهر مرة أخرى.

## 3. التعديل من داخل المنصة

1. افتح رابط المنصة.
2. **اضغط على شعار سنكري 3 مرات متتالية بسرعة.** يظهر شريط التحرير في أسفل الصفحة.
3. اضغط على أي نص وعدّله مكانه. النصوص القابلة للتعديل تظهر حولها حدود منقطة.
   - **+ إضافة**: يضيف بنداً أو بطاقة أو صفاً أو مرحلة أو منصباً.
   - **×**: يحذف العنصر.
   - **أسماء التبويبات**: تظهر أعلى كل قسم في وضع التحرير، ويمكن تعديلها من هناك.
   - غرف المركز: اضغط على الغرفة في المخطط، ثم عدّل اسمها ومساحتها ووظيفتها في البطاقة تحت المخطط.
4. اضغط **حفظ**.
   - في أول مرة تظهر نافذة **الإعدادات**: الحساب والمستودع يُملآن تلقائياً، الصق المفتاح فقط واضغط «حفظ الإعدادات»، ثم اضغط **حفظ** مرة أخرى.
5. خلال دقيقة أو دقيقتين تظهر التعديلات لكل من يفتح الرابط. على جهازك تظهر فوراً.

**ملاحظات:**
- التعديلات غير المحفوظة تبقى على جهازك حتى لو أُغلقت الصفحة، وتعود عند الدخول لوضع التحرير مرة أخرى.
- **خروج** دون حفظ يسألك أولاً، ثم يحذف التعديلات غير المحفوظة.
- **تنزيل نسخة** يحفظ ملف `content.json` على جهازك كنسخة احتياطية، أو لرفعه يدوياً.
- المفتاح يُحفظ على الجهاز الذي أدخلته فيه فقط. على جهاز آخر تحتاج إدخاله مرة أخرى. ومن **الإعدادات ← حذف المفتاح من هذا الجهاز** تزيله متى شئت.

---

## 4. طريقة احتياطية: التعديل من موقع GitHub

افتح `content.json` في المستودع، واضغط أيقونة القلم، وعدّل النص بين علامتي التنصيص `"..."`، ثم **Commit changes**. المنصة تُنشر تلقائياً.

انتبه ألا تحذف علامات التنصيص أو الفواصل بين العناصر.

## 5. إذا ظهرت مشكلة

| الرسالة | الحل |
|---|---|
| «المفتاح غير صالح أو لا يملك صلاحية الكتابة» | أنشئ مفتاحاً جديداً وتأكد أن صلاحية **Contents** هي **Read and write** وأنه مربوط بمستودع المنصة. |
| «تعذّر الوصول إلى المستودع» | افتح **الإعدادات** وتحقق من اسم الحساب واسم المستودع والفرع (`main`). |
| «لا يمكن الاتصال بـ GitHub من هنا» | أنت تفتح المنصة من مكان غير GitHub Pages. افتحها من رابطها. |
| حفظت لكن التعديل لم يظهر للآخرين | انتظر دقيقتين، ثم تأكد من تبويب **Actions** أن النشر انتهى بعلامة خضراء. |
